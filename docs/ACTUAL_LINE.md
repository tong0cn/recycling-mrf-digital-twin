# 桐乡实际分拣线：工艺与 CAD 核查

基于本轮核查的独立运行动画已新增，入口、运行方法和验证见 [实际产线动画](./ACTUAL_ANIMATION.md)。以下保留布局核查阶段的范围与记录。

## 本轮范围

根据用户提供的 `桐乡分拣线.STEP` 建立编号模型、装配清单和布局核查预览。本轮不替换原程序化演示，不实现新产线动画，也不把未核对的装配名称直接映射为工艺设备。

原始 CAD 及衍生模型仅保存在本地；不纳入本次 Git 提交或 Pages 发布。预览通过本地 HTTP 服务访问，Three.js 依赖取自已有的 `node_modules`。

## 已确认工艺（用户说明，2026-10-19）

来料为废旧混合塑料瓶。

1. 爬坡机上料，进入第一台分选设备。
2. 第一台设备分出三色瓶（PET）与其他杂瓶，两路分别由风机送入两个中转料仓。
3. 杂瓶中转仓经另一台爬坡机送到中间人工分拣平台；人工分出大白、小白、花乙、油壶、易拉罐，进入独立小仓位。
4. 三色瓶中转仓经螺旋上料机进入脱标机，之后经爬坡机进入第二台分选设备。
5. 第二台设备直接分出 3A（透明高质量 PET），经风送进入 3A 成品仓。
6. 其余瓶料经输送带进入并联机械手分拣段，机械手分出绿瓶、棕瓶至独立小仓位；剩余杂色 PET 经风送进入另一成品仓。
7. 3A 和杂色 PET 成品仓达到阈值后，经仓底开口、共用输送带、链板机进入打包机。一次只打开一个成品仓。
8. 小仓位物料打包时由人工运送到打包机。具体搬运容器、投料位置和操作细节尚未确认。

人工分拣剩余料、脱除标签不表现。用户未要求真实气固两相流、瓶体碰撞或脱标机理求解，后续以工艺动画和可校准的流量模型实现。

- CAD 原始名称、独立实例编号与拟定工艺职责分开保存。
- 四个同名 `TX-料仓总装` 已由用户确认：E02 三色中转、E03 杂瓶中转、E04 3A 成品、E05 杂色 PET 成品。
- 两个同名 `AI分选机总装` 已由用户确认：E17 第一台、E18 第二台。
- `总装配0`（E10）确认为链板机，`ZJ001-300-001`（E15）确认为并联机械手；其他辅助装配继续保留原名。
- 编号是当前文件快照的实例编号，不作为跨 CAD 版本的永久设备 ID。
- 包围尺寸为模型轴向包围盒，用于布局核查；不等同于制造图外形标注或现场测量。

## 检查工具

参考现有 `spatial/layout.ts` 的共享几何思路、`tests/scene.test.ts` 的空间一致性核查，以及 `docs/VALIDATION.md` / `docs/screenshots/README.md` 的验证记录方式。本轮另建 CAD 核查工具，不改原应用。

Python 工具使用独立的 Open CASCADE 绑定：

```powershell
python -m venv <独立环境目录>
<独立环境目录>/Scripts/python -m pip install cadquery-ocp==7.9.3.1.1
<独立环境目录>/Scripts/python scripts/inspect-step.py '桐乡分拣线.STEP' --output docs/cad-local --mesh
Copy-Item scripts/cad-review.html docs/cad-local/index.html
python -m http.server 5216 --bind 127.0.0.1
```

访问 `http://127.0.0.1:5216/docs/cad-local/`。本地目录已通过 `.git/info/exclude` 排除，不影响其他开发者的忽略规则。

输出包含 `inventory.json`（原始名称、实例编号、坐标、尺寸、源文件 SHA-256）和 `plant.glb`（保留装配结构的核查网格）。网格采用 8 mm 绝对弦差和 0.5 rad 角度参数，目标是布局核查；该参数不代表最终模型尺寸误差上限，也不保证已经达到生产端的性能预算。

完整转换网格仍包含大量按曲面拆分的绘制批次。另生成布局专用简化版：

```powershell
python scripts/prepare-cad-review.py docs/cad-local/plant.glb docs/cad-local/plant-merge-input.glb
npx --yes gltfpack@1.3.0 -i docs/cad-local/plant-merge-input.glb -o docs/cad-local/plant-review.glb -kn -si 0.2 -se 0.0002 -vpf -cc -v -r docs/cad-local/optimization.json
```

简化版保留 42 个顶层编号和材质，合并下级零件供布局核对，不能直接用于逐个运动部件的动画。页面使用已有 Three.js 中的本地 Meshopt 解码器。`-vpf` 避免整数位置量化对细长 CAD 构件的精度问题；简化误差参数是工具的相对误差控制，不等同于工程尺寸公差。

工具回归测试：`python -m unittest discover -s scripts -p 'test_*.py' -v`。

## 本轮验证结果

- STEP 成功经 Open CASCADE 加载；42 个顶层实例名称通过原始 `NAUO` 实例引用解析，四个同名料仓分别编号，不通过导入顺序猜测名称。
- 原文件 SHA-256 与首次生成清单时一致；原文件未被写入。
- 完整转换网格约 172.89 MB；布局简化版约 5.83 MB。按实例计算的三角形从 7,040,579 降至 1,554,451。后者仍需在正式动画制作时按设备和运动部件继续优化，未宣称达到移动端性能目标。
- 两版 GLB 均保留全部 42 个编号，每个编号节点下都有几何。
- `node scripts/verify-cad-review.mjs docs/cad-local/plant.glb docs/cad-local/plant-review.glb docs/cad-local/geometry-check.json` 通过；逐顶点变换后比较包围边界，两版最大偏差约 1.407 mm。该检查不等同于与原始 CAD 曲面的距离比较或工程公差验证。
- Python 工具 4 项回归测试通过，覆盖重复实例、中文名称、装配缺失拒绝、GLB 实例名称与变换保留、二进制几何不变及防止覆盖源导出。
- 浏览器已验证 42/42 加载、编号俯视、E04 独立查看及尺寸显示、全景与厂房显隐。预览朝向通过导出边界与 CAD 轴向尺寸匹配核对，不直接假定导出器默认轴向转换。
- `equipment.md` 和 `numbered-top.png` 位于本地 `docs/cad-local/`。设备清单已于 2026-10-20 更新为用户确认的 17 个核心设备对应，原装配名和尺寸同时保留。
- 本轮未修改应用源码，未运行应用的 npm 测试和构建；未实现新工艺动画、验证设备内部运动轴或校准生产节拍。

# RELOOP MRF 可回收物分拣中心数字孪生 · 完整复现提示词

本提示词根据最终源码、实际交互与已验证的测试整理而成，用于从零重建本目录。它补充而不替代 README 中逐字保留的原始需求；原始需求只描述了想做什么，这里描述的是**最终做成了什么**。

## 目标与前提

在工作区根目录新建 `recycling-mrf-digital-twin/`，做一个面向客户交流的可回收物分拣中心三维数字孪生。技术栈固定为 React 19 + TypeScript + Vite 6 + Three.js 0.177 + React Three Fiber 9 + Drei 10，测试用 Vitest + Testing Library。要求：除依赖安装外，页面运行不得请求任何 CDN、在线模型、在线字体或第三方接口；所有几何与视觉由代码生成。

## 一、工艺与场地

厂房 40 × 26 m，X 轴向右、Z 轴向内，地面为 ±0。分区与坐标（2026-10-19 按客户反馈重排，两条线单向流动、互不交叉，所有实体包围盒互不重叠且不侵入主通道）：

- 原料缓存区 `(-11.6, -8.8)`，6.0 × 2.6；成品缓存区 `(6.2, -8.8)`，4.4 × 2.6。
- 主通道在 Z = 4.2，宽 3.4 m（2.5…5.9），跨全厂；叉车跨区搬运必须经过它，同一时刻只允许一台进入。**没有任何设备包围盒进入这条带**。

## 二、仿真内核（必须先做，且不依赖 three）

1. **步长与纯函数**：固定步长 1/30 s；状态是「步数 + 干预日志」的纯函数。任何随机都必须来自种子化的 mulberry32，禁止 `Math.random()`。同一步数必须得到同一状态，因此时钟只能整步推进。
2. **干预日志**：命令形如 `{at, device, key, value, flag}`。求值时按 `at` 排序，只应用 `stepOfTime(at) <= 当前步` 的命令，其中 `stepOfTime(t) = max(0, ceil(t / STEP - 1e-9))`（epsilon 保证整步记录的时刻落在本步而不是下一步）。写入命令后必须**重放当前步**（重算而不是跳过），否则实时播放与拖动重放会差一步。丢弃步号不小于该命令的关键帧缓存，再重放到当前时刻；拖到干预之前，历史状态自然还原。
3. **异常开关的同步**：异常标志必须在每次步进、跳转与重放之后都从设置同步到状态，否则时钟暂停时切换开关不会反映到状态、报警与顶栏横幅上。
4. **循环与关键帧**：每 5 s 存一份状态快照。拖动时间轴时从最近的关键帧重放，得到与直进完全一致的状态。到达班次末尾时把厂内物理状态重置为初值，只保留班次计数与累计台账。
5. **给料速率自适应**：给料不是「到点就停」，而是按「本班来料必须在不晚于 `FEED_DONE_AT` 之前全部上线」反推间隔，即 `min(额定间隔, 剩余预算 / 剩余包数)`。这样把速率调到下限也不会让料包滞留在料斗里。
6. **班末清场（演示约定）**：从 `FINAL_SWEEP_AT` 起只执行一次，把仍在厂内的包装（不含仍在进货货车上、尚未收货的料包）计入出场、把未完成的打包块标记为已出厂、清空料仓与存储区、作废未完成任务与机械臂队列，并把叉车归位（停机或距离过远时直接停回起始位）。默认参数下现场在清场之前就已自然闭合，测试对此有断言；但清场是保证循环无缝的兜底。
7. **物料单元**：每个单元有 `id / kind / origin / material / stage / s / decided / baleId / carrier`。`s` 是在当前皮带上的行进距离，皮带的 `from/to/fromY/toY` 既决定仿真的段长，也决定三维里物料的位置，二者必须同源。
8. **守恒台账**：收到料包时记 `received`，出厂时记 `shipped`（按出厂材质）与 `shippedByOrigin`（按收货材质），质量按**收货材质**折算。不变量是「已收货 = 已出厂 + 在厂」，其中仍在进货货车上的料包不算已收货；`lost` 只作为泄漏探针，任何时刻都必须为 0。台账由单一的 `shipUnit` 出口负责，天然幂等。
9. **装卸一致**：动态任务在**装货**时按取货点的现场物料收集，在**卸货**时必须改由叉车自己记录的在载货物解析，否则已装车的料包会匹配不到、永远卸不了货。
10. **阶段划分**：车 → 缓存 → 被搬运 → 料斗/铺料缓存 → 皮带各段 → 料仓 → 打包 → 待运 → 出厂；纺织线还有机械臂取件与转运阶段。

## 三、工艺流程细节

- **给料与输送**：给料速率为 8 包/分（可调 3–12），带速默认 1.1 m/s（可调 0.4–1.6）。带速为 0 时全线停住。
- **两级光选**：光选机 #1 只识别 PET、#2 只识别 HDPE，次序不可颠倒。命中判定为 `draw(seed, unitId, salt) < 效率`，效率 = 阈值 ×（0.55 + 0.09 × 气吹压力 bar），异常开关「光选误判」再乘 0.65。未命中的瓶料继续向后，最终成为尾料进入杂项区。
- **料仓与打包**：PET / HDPE 容量 6、阈值 3；棉 / 涤纶 / 混纺容量 4、阈值 2。达到阈值时把料仓**当前全部存量**送入打包机（这样质量台账严格守恒），打包周期塑料 5 s、纺织 4 s、纸板 5 s，班末 96 s 处强制清仓一次。
- **机械臂**：单臂串行，默认节拍 2 s/件（可调 1.4–5），四个阶段按 28% / 16% / 34% / 22% 分配，取件位在 `(-4.6, 8.4)`。
- **高光谱**：识别成功按来料材质入仓，失败则转杂项。
- **纸板与杂项**：不进入分拣线，卸货后由叉车入库；纸板积到 2 包自动打包成 1 个纸板包；杂项连同尾料一起由转运货车 B 回程装走。

## 五、三维表现

视觉方向是**程序化微缩沙盘**（2026-10-16 由「低多边形平涂」升级而来，理由：平涂语言下构件过薄、无阴影无环境光，客户反馈「简陋」）。硬约束不变：不得出现任何外部图片、模型、字体或 CDN 资源 —— 贴图靠 Canvas2D 在运行时画出来。

- **光**：三点光（暖色主光 3.6 承担投影 + 冷色轮廓光 0.42 + 暖补光 0.3）+ 半球光 0.24 + 环境光 0.1；`<Canvas shadows="soft">` 开真阴影（2048²、`normalBias`），`RoomEnvironment` + PMREM 生成环境贴图（three 自带、无需 HDR 文件，强度 0.3），`ACESFilmic` + `toneMappingExposure` 1.08，雾用 `fogExp2` 0.0034 且**与背景同色**（`#9fb2bd`）。屋里只用 3 盏不可见的 `pointLight` 补光——**吊顶灯带不做实体几何**，那些横在视线上的自发光长条会挡住设备。
- **后处理**：`@react-three/postprocessing` 的 Bloom（阈值 0.82、强度 0.5，只吃自发光件）+ Vignette；指示灯、屏幕、门楣灯因此有光晕。
- **阶调**：地坪 `#b9c1c5`、墙板 `#d5dbde`、屋面 `#a9b3b9`、底座侧面 `#59646b` —— 主体走浅色高调、靠深色底座与深色机架压住画面；目标是三维视口亮度直方图 p01 ≈0.15、p50 ≈0.6，既有暗部也有高光。设备用高饱和蓝 `#3f7fa3` 配安全黄 `#f5c62d` / 橙 `#ef8a2c`，四种物料的分选色也全部加饱和。
- **构件密度**：`scene/kit.tsx` 提供倒角板（RoundedBox）、任意两点方管/圆管、护栏、脚座、线缆槽、电机、百叶、螺栓排、检修梯、木托盘、控制柜、状态灯等参数化原语；设备普遍由 3–6 个基础体提升到 20–60 个构件。
- **厂房**：沙盘底座、园区前场（货车停靠、倒车与地磅所在的场地，带车道虚线）、混凝土地坪（含伸缩缝与米级油渍）、环氧通道与安全黄划线、分区色块与**刷在地面上的分区名**、钢柱、屋面桁架与檩条（只在实体屋顶时出现）、两组采光带、三组卷帘门与卸货雨棚、防撞柱、短段防护栏杆（不再用一道长栏把厂房切成两半）、月台标识板、长边厂牌。
- **贴图**：`scene/textures.ts` 用 Canvas2D + 固定种子生成混凝土地坪、环氧通道、彩钢瓦墙板、橡胶皮带、瓦楞纸板、木托盘、警示斜纹与文字贴花（分区名 / 铭牌），按「族 + 重复次数」缓存；取不到 2D 上下文时自动退回纯色。
- **色彩**：`scene/palette.ts` 是唯一色彩事实源，`scene/materials.ts` 把「表面类型」映射为 roughness / metalness / envMapIntensity，场景文件里不再出现散落的十六进制字面量。
- 厂房墙体在透视模式下淡出（0.14）并隐藏屋面与墙板肋条，实体屋顶模式下显示完整外观、同时**隐藏悬浮标签**（`Html` 是 DOM 覆盖层，不受几何遮挡，否则会浮在屋面上）。
- 设备用参数化几何拼装：料仓为半透明筒体 + 加强环 + 锥底 + 支腿 + 爬梯 + 料位柱与侧向料位灯带；打包机为压缩室 + 料斗 + 液压站与油管 + 操作柜 + 安全门；机械臂为底座 + 两级臂 + 腕部 + 双指夹爪 + 线缆包；光选机为机架 + 相机罩 + 气吹阀排 + 分选色罩；叉车含护顶架、门架、货叉、警示灯；货车含导流罩、车厢波纹肋、六轮（轮辋 + 螺栓）、灯组与挡泥板。
- 物料单元按 `kind` 用瓶包（圆柱 + 捆扎带）/ 织物软包 / 纸板垛表示，颜色取 `origin`，因此能看到「一个 PET 瓶落进了杂项区」。
- 场景层与面板层解耦：三维在 `useFrame` 里直接读时钟实例（不触发 React 渲染），面板以约 8 Hz 刷新。

## 七、验收标准

必须全部满足，否则视为未完成：

1. 物料守恒在每一步都精确成立，丢失计数恒为 0。
2. 料仓存量始终在 `[0, 容量]` 内；打包只在达到阈值或班末清仓时触发，且触发时料仓确实持有足够的包。
3. PET 必须先于 HDPE 被分出；降低气吹压力只会把瓶料转成尾料，不会让物料消失。
4. 单行主通道同一时刻最多一台叉车；跨区路径必须经过主通道；两台叉车不同位。
5. 同一步数必然得到相同状态；暂停、倍速、重置、拖动、带干预重放的结果一致；第二个班次与第一个班次逐位一致。
6. 班次结束时厂内回到初始物理状态（全部出厂、无残留、车辆离场、叉车归位），且默认参数下在清场时刻之前就已自然闭合。
7. 看板每一行满足「进料 = 出货 + 在厂」；在厂口径不含仍在进货货车上的料包。
8. 时间轴里程碑与真实仿真的偏差不超过 2 秒。
9. 构建产物只引用相对资源，不含 CDN 主机名、在线字体或 sourcemap 引用；程序化贴图必须是运行时 Canvas2D 生成，不得引入任何图片文件。
10. 在 1440 / 1024 / 900 / 390 px 四档视口下，界面元素两两不重叠（里程碑标签互不压字、相机按钮不压时间轴、三栏与操作提示不互相覆盖），且没有横向溢出；窄屏下设备列表、场景、详情与看板依次堆叠，**只由 `.app-shell` 一个容器滚动**（`html/body` 锁 `overflow: hidden`，否则会多出一段滚得到但什么都没有的空白），竖屏机位按宽高比拉远以保证整块沙盘入画。
11. 生产构建在 1440×900 下实测帧率不低于 55 FPS（本机 headless Chromium + ANGLE D3D11 / RTX 4070 Laptop：暂停 151 FPS、1 倍速 122 FPS；headless 的 rAF 不受 vsync 限制，这是渲染上限而非屏幕刷新率）。
12. 浮在三维画面上的文字（操作提示、材质图例）必须自带底衬或描边，对比度不低于 4.5:1 —— 深色面板的 `--muted` 压在浅色场景上只有 ≈1:1。
